# QORE DEEPSEEK EXPERT — WORK ROADMAP V1

## Status

CANONICAL ROADMAP for External DeepSeek Expert validation of Harness-produced QORE Core candidates.

This roadmap is persistent repository policy. It applies across chats, projects, PRs and work packages unless the Integration Authority explicitly supersedes it in GitHub.

## Purpose

External Expert is the independent adversarial validator AFTER Harness has completed its own dual-role one-shot process.

The intended quality pipeline is:

`HARNESS_ENGINEER_MODE`
-> `6 SUBAGENT ENGINEERING / FAMILY CLOSURE`
-> `CANDIDATE`
-> `HARNESS_INTERNAL_EXPERT_MODE`
-> `6 SUBAGENT ADVERSARIAL FALSIFICATION`
-> if material finding: `RETURN TO HARNESS_ENGINEER_MODE INSIDE SAME WORK PACKAGE`
-> repeat until `HARNESS_INTERNAL_EXPERT_STATUS: CLEAN`
-> `EXTERNAL FULL QG`
-> `MATERIALIZE / EXACT-HEAD CI / FREEZE`
-> `EXTERNAL DEEPSEEK EXPERT`
-> expected target: `VALIDACIÓN OK`
-> `IA ADJUDICATION`
-> only then `DEEPSEEK CODER`.

## Entry requirement for External Expert

External Expert must not treat a normal Harness candidate as ready merely because Harness edited code or focused tests passed.

For Harness-originated work, the handoff package should carry evidence that the exact candidate completed:
- Harness Engineer Mode;
- exactly 6/6 required Harness subagent identities;
- root-family/FAMILY_MODEL closure for assigned material scope;
- Harness Internal Expert Mode after final implementation;
- six adversarial specialties over the candidate;
- zero known material issue intentionally deferred to External Expert;
- final Internal Expert clean status on the unchanged candidate;
- canonical FULL QG and exact candidate binding before freeze.

Canonical prerequisite markers:

`HARNESS_INTERNAL_EXPERT_STATUS: CLEAN`

`HARNESS_DUAL_ROLE_STATUS: ENGINEER_COMPLETE + INTERNAL_EXPERT_CLEAN`

If required dual-role evidence is absent, inconsistent with the exact candidate, or predates a semantic mutation, External Expert must report an intake/gate deficiency to the Integration Authority. It must not infer that Harness performed the internal adversarial phase.

## External Expert remains independent

Hard laws:

`INTERNAL EXPERT CLEAN != EXTERNAL EXPERT PASS`

`EXTERNAL EXPERT DOES NOT TRUST HARNESS BY ASSERTION`

`EXTERNAL EXPERT REMAINS READ-ONLY AND ADVERSARIAL`

`GREEN QG != SEMANTIC CLEAN`

`EXPERT PASS MUST BE EARNED INDEPENDENTLY`

The internal Expert inside Harness exists to improve the candidate before handoff. It does not replace External Expert and does not weaken External Expert's five-subagent, semantic-LSP, HIGH/MAX, checkpoint, root-family or cross-interaction obligations.

External Expert must treat Harness closure arguments, Internal Expert clean claims, tests and FAMILY_MODELs as hypotheses to falsify.

## Acceptance expectation

Every Harness delivery has this explicit acceptance target:

`EXTERNAL EXPERT EXPECTED PASS`

That is a quality target for Harness, NOT an instruction to External Expert to return PASS.

External Expert must still attempt to break the exact frozen candidate with independent evidence.

If it finds no material defect and all mandatory review evidence is complete, normal result is:

`HALLAZGOS: NINGUNO`

`VALIDACIÓN OK`

## Material escape classification

If External Expert discovers a material defect in a candidate that Harness certified as `INTERNAL_EXPERT_CLEAN`, the event is NOT considered a normal expected correction cycle.

Classify it as:

`HARNESS_QUALITY_FAILURE`

External Expert must record:
- exact material witness;
- root family/invariant;
- why the defect was reachable under Harness's assigned scope;
- which Internal Expert adversarial specialty or FAMILY_MODEL dimension should reasonably have exposed it;
- whether the defect arose from a post-internal-clean candidate mutation, missing intake evidence, or genuine Harness escape.

The Integration Authority then decides remediation. Coder remains blocked while any material Expert finding exists.

The objective is to improve/fix the Harness method rather than normalize an endless `Correction-N` chain.

## Mandatory External Expert sequence

For each Harness-originated frozen candidate:

1. Verify exact BASE/HEAD/TREE/SYNTHETIC/QG/freeze binding.
2. Verify the Harness dual-role intake evidence is bound to the candidate lineage.
3. Build the External Expert SHARED_EVIDENCE_MAP.
4. Execute the mandatory five independent Expert lanes.
5. Use semantic LSP in the primary Expert session and supplemental subagent LSP as applicable.
6. Challenge Harness FAMILY_MODEL completeness and Internal Expert attack coverage.
7. Generate fresh witnesses rather than merely replaying Harness probes.
8. Attack historical regressions and second-order cross-interactions.
9. Adjudicate all proposed findings independently.
10. Return `VALIDACIÓN OK`, `VALIDACIÓN NO OK`, or `VALIDATION BLOCKED` according to evidence.

## Relationship to Harness's six subagents

Harness's six subagents and External Expert's five subagents are intentionally separate layers.

Harness 6/6 objective:
- discover and fix problems BEFORE handoff;
- support Engineer Mode;
- support Internal Expert Mode;
- leave candidate internally clean.

External Expert 5/5 objective:
- independently falsify the frozen result;
- detect any escaped semantic defect;
- verify Harness did not mistake self-consistency for correctness.

The External Expert may use knowledge of Harness's internal attack matrix to choose unexplored orthogonal attacks, but must not inherit Harness conclusions as authoritative.

## No correction treadmill doctrine

The intended lifecycle is:

`ONE HARNESS WORK PACKAGE -> ONE INTERNALLY CLEAN DELIVERY -> ONE EXTERNAL EXPERT VALIDATION`

Repeated correction rounds are a failure mode, not a scheduling primitive.

If External Expert finds a material escape, preserve the evidence and repair the responsible causal family/method, but do not redefine repeated escapes as normal progress.

## Cost and time doctrine

Quality is above speed. Harness is allowed to spend a longer bounded execution, including approximately two hours where permitted, because a complete Engineer + Internal Expert cycle is preferable to many repeated Harness/Expert paid rounds.

External Expert must not lower review quality to preserve the expected PASS target.

## Final responsibility split

Harness responsibility:
`BUILD + BREAK OWN BUILD + FIX UNTIL INTERNAL CLEAN`

External Expert responsibility:
`BREAK INDEPENDENTLY OR CERTIFY NO MATERIAL FINDING`

Integration Authority responsibility:
`VERIFY BINDINGS + ADJUDICATE + CONTROL NEXT GATE`

Coder entry law:
`NO EXTERNAL EXPERT PASS + NO IA PASS = CODER BLOCKED`
